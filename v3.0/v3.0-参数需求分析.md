## 三、奖金计算的 6 大已知坑点

### 坑点1: 双色球/大乐透的「两部分封顶」

**问题**: 当奖池>=1亿时，一等奖分两部分计算，每部分**各自独立**封顶500万，理论上单注可达1000万。

**正确逻辑**:
```python
part1_per_ticket = min(part1 // win_count, 5000000)
part2_per_ticket = min(part2 // win_count, 5000000)
result = part1_per_ticket + part2_per_ticket  # 可达1000万
```

**常见错误**: 只封顶一次（500万），或者总额封顶1000万（正确应是各部分独立封顶）。

### 坑点2: 保底规则的级联效应

**问题**: 保底规则有执行顺序，后触发的可能覆盖先触发的。

**双色球保底顺序**:
1. 先算基本浮动奖
2. 检查「一等奖 >= 二等奖×2」
3. 检查「二等奖 >= 6000」
4. 若二等奖被提至6000，**再检查**「一等奖 >= 12000」（6000×2）

**常见错误**: 只执行一次保底检查，忽略了级联。

### 坑点3: 大乐透保底与双色球不同

**双色球**: 二等奖保底 = 6000元（固定值）
**大乐透**: 二等奖保底 = 三等奖×2（动态值）
- 奖池<8亿: 三等奖=5000, 保底=10000
- 奖池>=8亿: 三等奖=10000, 保底=20000

### 坑点4: 大乐透追加投注的奖金计算

**正确逻辑**:
```python
# 追加投注中浮动奖
bonus = base_prize * 0.8  # 提升80%
total_per_ticket = base_prize + bonus  # = base_prize * 1.8
# 封顶: 基本封顶500万, 追加封顶900万
total_per_ticket = min(total_per_ticket, 9000000)
```

**常见错误**: 
- 把1.8倍当成"提升到1.8倍"而非"提升80%"
- 二等奖也参与追加（实际规则是仅浮动奖参与）

### 坑点5: 七星彩的「倒置」规则

**正确逻辑**:
```python
if prize_pool > 300000000:  # 奖池>3亿
    first_ratio = 0.10   # 一等奖只拿10%
    second_ratio = 0.90  # 二等奖拿90%
else:
    first_ratio = 0.90   # 一等奖拿90%
    second_ratio = 0.10  # 二等奖拿10%
# 注意: 倒置时一等奖仍叠加奖池
```

**常见错误**: 倒置时忘记一等奖仍然叠加奖池资金。

### 坑点6: 福彩3D/排列三的中奖判断逻辑完全不同

**直选**: 必须按位匹配 → `[[1,1,1]]`（百位、十位、个位各中1个）
**组三**: 不按位，任意2位匹配 → 需要判断开奖号是否为对子
**组六**: 不按位，3位全匹配 → `[[3]]`（总命中数=3）

**常见错误**: 后端用统一的 `match_counts == pattern` 无法区分组三和组六。

## 五、配置系统设计建议

### 5.1 关键改进点（vs v2.0）

1. **统一 matchPattern 语义**: 所有彩种的 matchPattern 都用 `[区1命中数, 区2命中数, ...]` 表示
2. **新增 matchType 字段**: 支持 positional（按位匹配）、unordered（不按位匹配）、hybrid（混合）
3. **新增条件触发规则**: 福运奖等需要条件触发的奖级，使用 `conditionalPrizes` 数组
4. **保底规则参数化**: 将保底逻辑从硬编码改为配置驱动
5. **固定奖提档参数化**: 使用 `highPoolThreshold` + `highPoolAmount` 描述提档规则

## 六、实施建议

### 6.1 优先级排序

1. **P0 — 必须解决**: 奖金计算的6大坑点（两部分封顶、保底级联、3D/排列三匹配逻辑）
2. **P0 — 必须解决**: 配置系统能完整复现8种官方彩种
3. **P1 — 重要**: 前端配置编辑器
4. **P2 — 可延后**: 额外彩种支持（海外彩票等）

### 6.2 测试验证策略

**每种彩种至少需要验证以下场景**:

1. **常规场景**: 正常中奖，奖金正确
2. **浮动奖封顶**: 单注奖金达到封顶值
3. **总额封顶**: 奖级总奖金达到封顶值
4. **保底触发**: 保底规则生效，奖金被补足
5. **奖池分档切换**: 奖池跨越分档阈值时的计算
6. **极端场景**: 大量中奖注数时的精度
7. **复式/胆拖**: 组合数计算正确
8. **追加投注**: 大乐透追加奖金正确

## 七、总结

### 改造可行性: ✅ 完全可行

### 关键风险点
1. 奖金计算的级联逻辑容易出错（保底、封顶、提档的执行顺序）
2. 福彩3D/排列三的按位/不按位匹配需要在配置层面区分
3. 快乐8的多玩法+固定开20个号码需要特殊处理
4. 前后端配置必须完全一致（v2.0已存在不一致问题）

### 预估工作量调整
- 原计划: 2-3周
- 调整后: **3-4周**（增加1周用于奖金计算的全面测试和边界条件处理）
