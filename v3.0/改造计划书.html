📋 一、项目概述

核心目标：将现有支持固定 8 种彩票的模拟器，改造为可以通过参数配置支持任意彩票类型的通用自定义模拟器平台。

1.1 当前状态

v2.0 版本已支持 8 种中国彩票（双色球、大乐透、福彩3D、七星彩、排列三、排列五、七乐彩、快乐8），但配置硬编码在代码中，用户无法自定义。

1.2 目标状态

v3.0 版本将实现：

  • 可视化配置界面 — 用户通过表单创建自定义彩票类型
  • 参数化核心引擎 — 所有计算逻辑基于配置动态执行
  • 配置导入/导出 — 支持 JSON 格式，方便分享和复用
  • 预设模板 — 保留原有 8 种彩票作为预设

⚙️ 三、配置系统设计

3.1 配置数据结构

通用彩票配置采用 JSON 格式，包含以下核心字段：

{ "id": "custom_lottery", "name": "自定义乐透", "price": 2, "currency": "¥", "returnRate": 0.51, // 号码区域配置 "zones": [ { "name": "前区", "min": 1, "max": 40, "count": 5, "repeatable": false, "color": "#e74c3c" }, { "name": "后区", "min": 1, "max": 12, "count": 2, "repeatable": false, "color": "#3498db" } ], // 奖级配置 "prizes": [ { "level": 1, "name": "一等奖", "matchPattern": [[5, 2]], "fixed": false, "poolRatio": 0.7, "maxPerTicket": 5000000 }, { "level": 2, "name": "二等奖", "matchPattern": [[5, 1]], "fixed": true, "amount": 5000 } ], // 奖池配置（可选） "poolTiers": [...], // 高级选项 "options": { "canAddOn": false, "addOnPrice": 0, "hasSpecialNumber": false } }

3.2 配置验证规则

字段 类型 必填 验证规则
id string ✅ 唯一标识符，仅允许字母、数字、下划线
name string ✅ 显示名称，1-50 字符
price number ✅ 单注价格，大于 0
zones array ✅ 1-5 个区域
zones[].min number ✅ 号码最小值
zones[].max number ✅ 号码最大值，必须 > min
zones[].count number ✅ 选取数量，1 ≤ count ≤ max-min+1
prizes array ✅ 1-10 个奖级
prizes[].matchPattern array ✅ 中奖条件，每个区域的命中数

3.3 预设模板

预设保留：原有的 8 种彩票（双色球、大乐透、福彩3D、七星彩、排列三、排列五、七乐彩、快乐8）将作为预设模板保留，用户可以基于这些模板进行修改。

🔧 六、关键技术细节

6.1 奖金计算通用化

当前问题：双色球和大乐透有专门的奖金计算函数（calculate_ssq_tiered_prize、calculate_dlt_tiered_prize），包含硬编码逻辑。

解决方案：抽象为通用的分档奖金计算函数，通过配置参数控制计算逻辑：
  • poolTiers — 奖池分档配置
  • firstPrizeRatio — 一等奖比例
  • secondPrizeRatio — 二等奖比例
  • secondPartRatio — 二等奖第二部分比例（高奖池时）
  • guaranteeRules — 保底规则配置

6.2 前端动态渲染

当前问题：前端有大量针对特定彩票类型的判断逻辑（如 if (currentLottery === 'fc3d')）。

解决方案：

  • 基于配置动态生成选号界面
  • 使用模板引擎渲染号码球
  • 通过 CSS 变量控制颜色主题
  • 移除所有硬编码的彩票类型判断

6.3 配置导入/导出

功能 实现方式 说明
导出配置 JSON 文件下载 将当前配置导出为 .json 文件
导入配置 文件选择 + 验证 导入 .json 文件，自动验证格式
分享配置 Base64 编码 将配置编码为字符串，便于分享
